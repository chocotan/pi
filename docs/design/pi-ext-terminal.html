Width rules

120 columns: root application layout: 88-column left conversation + 2-column gap + fixed 30-column right sidebar. The left composer sits at the bottom; transcript scrolls above it. The right column starts at the top, has its own background and overflow, and spans the whole application height. Hide the sidebar to reclaim the full main width.

80 / 48 columns: the main input retains the entire available width. Todo / Subagents becomes a separate switchable panel using the prototype control above. Switching back preserves the draft and state.

At 48 columns, status and elapsed time move to a separate framed line. Metric groups wrap intact. Long paths keep their beginning and ending with a middle ellipsis; branches and task titles wrap. A smaller browser viewport reduces effective columns at the same 16px font size without horizontal scrolling.

Metric definitions and simulation details
↑ Session input
Cumulative input for this session: 12,400. It excludes the separately reported cache read and cache write categories. No combined session token total is shown.
↓ Session output
Cumulative output for this session: 3,200. Abbreviations use decimal k = 1,000.
Cache
Cumulative cacheRead for this session: 68,600. Cache writes do not count as hits and are not included in this value.
Cache writes · Detail
Cumulative session cacheWrite: 18,400, recorded here separately. Never added to the main Cache value or session input.
CH · Latest request
cacheRead / (input + cacheRead + cacheWrite) for the latest completed request with usage. Example: 19,900 / (80 + 19,900 + 20) = 99.5%. Output is excluded. Running preserves the preceding completed request's CH until fresh usage arrives. Unavailable usage or a zero denominator shows —.
Context
Current effective context usage / model context window / percentage: 38,400 / 200,000 = 19.2%. This is independent of session totals. Unknown current usage preserves a known limit: Context: —/200k · —. Unknown window and percentage must likewise show — in a real implementation.
Elapsed
Wall-clock time for the current turn. Suggested boundary: user submission to turn completion, including tool work. Running is frozen at 00:18 in this prototype; Done at 00:42, Stopped at 00:12, Failed at 00:07. No real timer runs.
Model / thinking
gpt-6.1-sol · high uses model ID and thinking level. The Thinking level control always updates a visible level on the border. Longer values wrap instead of hiding thinking level.
Auto compaction
(auto) remains beside Context in every main-view state, including unknown usage. It indicates automatic context compaction is enabled; it does not indicate that a compaction is currently running.
Conditional fields
Production integration must preserve the existing conditional W (cacheWrite), cost, sessionName, and virtual routed-model displays. They are intentionally absent from the default mock status bar, not proposed for removal. W stays separate from Cache hits; its mock session value is recorded above.
Directory / branch
Todo / Subagents
Future native features, represented by mock data. Todo uses pending / active / done text and counts; Subagents use running / done / failed / pending / stopped, elapsed, and task association. Empty, completed, stopped, and failed examples follow the display state. This panel performs no task operations.
Architecture and self-checks

One offline HTML file, inline CSS and native JavaScript. No dependencies, network calls, remote fonts, shadows, or pixel-rounded terminal borders. Border glyphs are ╭╮╰╯│─. The external selects and reset button control this preview only; they propose no new product shortcuts.

Structure: root application grid/flex with full-height left and right columns. Left: session header → scrollable transcript → bottom composer and footer. Right: Session → Todo → Subagents, independent of composer height. Existing CustomEditor border indicators and FooterComponent usage data can provide the composer fields. The sidebar awaits native task and agent state sources.

The character grid accounts for single-width ASCII and double-width CJK fixtures. Production integration should use the existing TUI Unicode width helper. Emoji, combining characters, IME behavior, actual terminal fonts, and service data are outside this display prototype.





Keyboard: Tab through labeled native controls and the read-only message. Arrow keys change selects. No sending, retrying, timing, service connection, or real Todo / Subagent execution is implemented.
