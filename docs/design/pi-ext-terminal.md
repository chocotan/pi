# pi-ext 终端界面设计

状态：设计已确认并按内置插件方式落地。所有产品界面文案使用英文，HTML 预览中的数字均为示例数据。

离线原型：[pi-ext-terminal.html](pi-ext-terminal.html)。提供列宽、主题、thinking level、运行状态和主区域 / 侧栏面板切换。原型不连接真实服务，不能发送消息或执行任务。

## 布局

采用整个会话视口的左右布局，参考 OpenCode：左侧为完整主区域（对话记录 + 底部输入框 + 状态栏），右侧为从视口顶部延伸到最底部的独立 Todo / Subagents 侧栏。侧栏与主区域是根布局的两个区域，不能只在底部与输入框并排。

左侧对话独立滚动，输入框固定在左侧底部；右侧顶部显示会话标题，Todo / Subagents 从上向下排列，侧栏内容可独立滚动。两区之间用一条细分隔线和主题背景层次区分，右侧不画成与输入框等高的小框。

输入区沿用 pi 编辑器和主题，使用 `╭ ╮ ╰ ╯ │ ─` 绘制圆角边框。

主区域：

- 顶边左侧：当前模型、thinking level，例如 `gpt-6.1-sol · high`；窄窗口优先缩写模型名，保留 level。
- 顶边右侧：`Ready / Running / Done / Stopped / Failed` 与本轮耗时。
- 框内：多行消息输入，保留中文输入法、光标、粘贴、历史和自动补全；示例内容使用英文。
- 框下第一行：当前工作目录、Git 分支。
- 框下第二行：`↑ 12.4k  ↓ 3.2k  Cache 68.6k  CH 99.5%`。输入、输出使用箭头，不完整显示 Input / Output 标签。
- 框下第三行：`Context 38.4k/200k · 19.2% (auto)`；`(auto)` 仅在自动压缩启用时显示，宽度足够可与 token 行合并。
- 保留现有条件性信息：会话名、缓存写入 `W`、费用、虚拟模型路由结果；宽度不足时放详细状态视图。

右侧栏：

- `Todo`：完成数 / 总数，当前任务、待办与已完成任务；用文字或符号明确状态，不只靠颜色。
- `Subagents`：代理名称、运行状态、各自耗时与关联任务；失败或停止明确标注。
- 无数据分别显示 `No tasks`、`No subagents`。
- 任务/代理详情通过现有命令或后续面板交互查看，不在输入框下重复显示摘要。

目录是当前操作的项目目录。`~/.pi-ext` 是全局配置和运行数据目录，两者分别显示和使用。

## 指标口径

| 字段 | 语义 | 界面示例 |
| --- | --- | --- |
| 模型 | 当前选择的 provider/model；长名称允许缩写，完整名称通过模型选择器查看 | `gpt-6.1-sol` |
| Thinking level | 复用 thinkingLevel，始终与模型关联显示；不支持推理的模型不显示，关闭推理时显示 `off` | `high` |
| 当前耗时 | 从接受本轮消息到最终 agent_settled 的墙钟时间，包含工具、重试和自动压缩；完成后保留，下一轮重置 | `Running 12.4s` |
| 当前目录 | 会话 cwd，home 缩写为 `~`；长目录保留末尾项目名称 | `~/Downloads/pi-ext` |
| 当前分支 | 复用 Git 分支缓存；非 Git 目录显示 `No Git`，detached HEAD 单独标注 | `main` |
| 输入 | 本会话累计非缓存输入 token，即现有 usage.input；不再并入缓存量 | `↑ 12.4k` |
| 输出 | 本会话累计输出 token，即 usage.output | `↓ 3.2k` |
| 缓存 | 本会话累计缓存读取 token，即 usage.cacheRead；cacheWrite 保留在详细统计中，不混作命中量 | `Cache 68.6k` |
| CH | 最近一次助手请求的 cacheRead / (input + cacheRead + cacheWrite)，不是会话平均值；无有效数据时显示 `—` | `CH 99.5%` |
| 上下文 | 使用 getContextUsage() 的估算值；与累计用量分开，未知时显示 `—/200k` | `Context 38.4k/200k · 19.2%` |

帮助说明解释 `↑ Input · ↓ Output · Cache read · CH latest request`，主状态栏只保留短标签。

压缩前用量、摘要和工具报告用量按现有统计继续累计。提供方不报告缓存数据时，不能通过 0 区分“不支持”和“未命中”，不推断缓存能力。

主代理与后台子代理的计时相互独立。主代理已完成、子代理仍运行时，输入框显示完成时间，侧栏继续显示子代理运行状态。

## 响应式规则

- 120 列：右侧栏约 28–32 列，贯穿整个会话视口；左侧剩余宽度同时用于对话、输入框与状态栏。
- 80 / 48 列：侧栏折叠为可切换面板，不挤压主输入区；仍可查看完整 Todo 和 Subagents。
- 模型过长时缩写，状态与耗时保持可见；必要时分行。
- 路径中间省略，token / cache / context 按完整字段换行，不截掉整个指标。
- 宽度计算使用终端可见列宽，中文字符和 ANSI 颜色不能按字符串长度计算。
- 输入框保留多行增长、内容滚动和原有自动补全位置。
- 面板切换若使用快捷键，必须加入可配置 keybindings，不能硬编码。

## 状态与颜色

沿用当前主题语义色：模型和焦点用 accent，辅助信息用 muted，完成用 success，错误用 error。侧栏与输入框使用相同边框风格。输入框边框继续跟随 thinking level 的主题色。原型提供浅 / 深主题切换，浅色以当前截图为参考。

## 当前 UI 核对

用户截图显示 `Working`、`~/Downloads/pi-ext (main)`、`↑332k ↓11k R3.6M CH98.3%`、`17.2%/1.0M (auto)` 和 `gpt-6.1-sol · high`。

源码 CustomEditor 还保留输入内容超出可见区时的 `↑ N more` / `↓ N more` 标记，运行状态包括压缩、重试和分支摘要。FooterComponent 条件显示缓存写入 W、费用、会话名、provider 和虚拟模型的实际路由结果，扩展状态另起一行。改版时需保持这些信息可访问。

## 上下文与完成状态

上下文超过 70% 用 warning，超过 90% 用 error，并保留数字。阈值沿用现有 footer，不新增配置。

初始显示 `Ready`，运行中显示 `Running` 与耗时，`Done / Stopped / Failed` 保留本轮耗时。压缩后尚无新响应时显示未知上下文，不能误显示 0%。

## 接入与验证

优先复用 CustomEditor、FooterComponent、InteractiveMode、FooterDataProvider 和会话统计。根 TUI 布局需划分左侧主区域与右侧全高度侧栏，输入框只属于左侧；处理各自区域宽度、焦点与独立滚动，不能只改底部 footer 的横向布局。

参考截图：当前 pi 输入区 `/tmp/muxlane-paste-image_01M4T5Z2G1AB49TCVVTFBWFHTG.png`；OpenCode 全高度侧栏 `/tmp/muxlane-paste-image_01M4T66J91WJ2PMGHF7F91T71T.png`。

验证包括 120 / 80 / 48 列、中文 / 长模型 / 长路径、侧栏显示与折叠、未知上下文、运行 / 停止 / 错误、重新打开与切换会话、主题切换、多行输入、自动补全和中文输入法光标。

## 原型验证结果

本机 Chromium + Playwright 验证通过：

- 504 组展示组合自检，无失败。
- 120 / 80 / 48 列精确显示，页面无水平溢出。
- 120 列右侧栏与主区域顶部、底部对齐，右侧栏高 756px。
- 窄屏面板切换后保留示例草稿。
- Thinking level 切换、浅 / 深主题、Failed 状态与未知上下文显示正确。
- 390px / 768px 浏览器窗口无水平溢出，浏览器无脚本错误。

最终截图：[宽屏](pi-ext-terminal.png)、[窄屏](pi-ext-terminal-narrow.png)。

HTML 原型只表达布局、字段和状态。当前生产 TUI 已接入内置 Todo / Subagents / ask-user 插件，真实 tmux + 本地 faux provider 验证了全高度侧栏、右侧鼠标详情入口、问卷回答、窄屏面板和默认折叠。539 项定向测试通过，真实 RPC e2e 在空 API 环境中明确跳过；实际中文输入法和所有终端图片协议尚未实机验证。
